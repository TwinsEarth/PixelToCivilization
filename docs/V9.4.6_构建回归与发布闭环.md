## 二、本轮根因链（r21→r26）

| 轮次 | 现象 | 证据 | 判定 |
|---|---|---|---|
| r21 | 开局 OOM 崩溃 | console 三连 [World]→[MARK_UI]→Could not allocate memory（2GB 上限） | 地形/水面网格延迟销毁同帧累积 |
| r22 | OOM 修复 | WorldGenerator 3 处 DestroyImmediate；构建 SUCCESS | 开局无 OOM，但 MARK_UI 越界仍现 |
| r23 | 越界定位 | UIManager.Update 加 step 标记 → step=Splash | 异常在 TickSplashAutoStart→StartNewRandomGame 链 |
| r24 | 循环开局实证 | [S1] regen→[S2] veg regrow 后无 [S3]，随即新一轮 [World] 重生成（11+ 次） | 卡点=VegetationSystem.Populate 内抛异常被吞 |
| r25 | 堆栈诊断失败 | 加 [VEGREG] try-catch 后开局直接 OOM（循环重建植被内存爆） | 需先断循环再定位；确立根因方向 |
| r26 | **根因修复** | **Populate 开头补 `_treeGrid.Clear()`** | 见下 |

### 根因（r26 确认）

`VegetationSystem.Populate` 开头只清了 `_sets/_sets3/Trees`，**漏清 V9.4.6 新增的树碰撞哈希网格 `_treeGrid`**。上一局树的旧索引残留在网格列表中，新局 `TreeOverlap` 遍历 `_treeGrid` 时执行 `Trees[旧idx]` → **ArgumentOutOfRangeException** → `StartNewRandomGame` 中断 → 启动页永不隐藏 → `TickSplashAutoStart` 每 10 秒自动开局 → 每局重建 1100+ 植被实例与合并网格 → 内存累积 → 崩溃/OOM。round23 偶发成功进入（种子未触发旧索引读）属巧合，不改变根因。

### 修复（一行 + 两道保险）

```csharp
// VegetationSystem.cs Populate() 开头
_sets.Clear(); _sets3.Clear();
Trees.Clear();
_treeGrid.Clear();   // V9.4.6r26 根因修复：清空上一局树格索引，否则 TreeOverlap 读旧 idx → 越界 → 开局必抛
LODManager.ClearCull();
```

保险一：`Regrow` 包 try-catch 打印 [VEGREG] 堆栈后 rethrow（防静默吞错）。
保险二：`Regrow` 的旧植被 `Destroy`→`DestroyImmediate`（r24，防延迟销毁累积）。
