# V9.4.7 统一跨阵营作战规则 · 策划裁决

> 基线：V9.4.6（体积碰撞 / 1949 坦克装甲车导弹车 / 高架桥柱连片）。本版在其上新增统一战斗目录，把五类作战单位接入同一套阵营判定、索敌、伤害分发，并使建筑（除树木外）可被破坏。先策划后开发，数值经 calculator 复算。

---

## 1. 问题诊断（根因）

五类作战单位分布在三个独立系统，**各自为战、只攻击本系统内的同类型敌人**：

| 作战单位 | 所在系统 | 现状索敌 | 阵营归属 |
|---|---|---|---|
| 军舰 | NavalSystem | `NearestEnemy` 只查 `EnemyShips` | 我方船 FactionId 空 / 敌舰 FactionId |
| 军车（坦克/装甲车/导弹车） | GroundWarfareSystem | `NearestEnemy` 只查 `Enemies`（GroundUnit） | Side="ours"/"enemy" + FactionId |
| 步兵（我方） | MilitarySystem | `NearestEnemy` 只查 Faction.Army（EnemyUnit） | FriendlyUnit |
| 塔防（箭/火/炮/碉堡） | MilitarySystem.UpdateTowers | 只查 Faction.Army（EnemyUnit） | 玩家建筑 |
| 骑兵（敌我） | MilitarySystem | 随步兵同链路 | EnemyUnit / FriendlyUnit |

**根因**：没有统一的"目标"抽象，各系统的索敌集合写死为自己的敌方列表，单位之间无法跨类型识别阵营；敌方各派之间也不互打；除 EnemyUnit 外，建筑、军舰、军车不被其他单位当作合法目标。

## 2. 设计目标（用户三条硬需求）

1. 作战单位：军舰、军车、军人、塔防、骑兵——五类齐全。
2. 五者之间，**不同阵营 & 势力之间自动攻击**（含敌方各派互相攻击）。
3. 除树木外，其他建筑都允许被破坏。

**胜负判断**：在一张同时存在我方五类单位、敌方多个阵营单位的地图上，任一单位都能自动锁定"阵营不同"的最近合法目标（不限类型）并开火；敌方建筑可被打到摧毁；树木始终不被任何单位选为目标。

## 3. 统一阵营键（FactionKey）

| 阵营 | FactionKey | 包含单位 |
|---|---|---|
| 我方（玩家文明） | `"PLAYER"` | 我方军舰、军车、FriendlyUnit（步/骑）、全部我方建筑（含塔） |
| 敌方各派 | 各派唯一名称 | 该派的军舰 / 军车 / 步骑部队 / 据点 |

**敌对判定（唯一规则）**：`A.FactionKey != B.FactionKey` 即敌对。
- 我方 Key 与所有敌方派 Key 不同 → 我方与所有敌方阵营敌对。
- 敌方阵营 A 与阵营 B 的 Key 不同 → 敌方各派之间也互相攻击（满足"不同势力之间"）。
- 同一 Key 内部为友军，不攻击、可支援。

> 敌方派名来源：NavalSystem 敌舰派系、GroundWarfareSystem 的 5 派（北方装甲军/沙漠军团/南方机械旅/东方突击师/联合远征军）、MilitarySystem 的五方（东夷/西戎/南蛮/北狄/中原诸侯）。命名互不冲突，即使跨系统也不会被误判为同一阵营；这正是期望的"群雄互相攻伐"。

## 4. 统一战斗目录（CombatSystem）

### 4.1 目标结构

```csharp
public class CombatTarget {
    public int Kind;          // 0军舰 1军车 2步兵 3塔 4骑兵 5建筑
    public object Ref;        // 原始对象引用：ShipEntity / GroundUnit / EnemyUnit / FriendlyUnit / BuildingEntity
    public float X, Z;        // 世界坐标
    public float Hp;          // 当前耐久
    public float Attack;      // 攻击力
    public float Range;       // 有效射程（世界单位）
    public string Key;        // 阵营键
}
```

### 4.2 目录重建（运行时态，4Hz）

- CombatSystem 每 **0.25 秒**（4Hz）调用各系统的 `RegisterCombat(this)` 清空重建 `Targets`。
- 注册顺序：NavalSystem（军舰）→ GroundWarfareSystem（军车）→ MilitarySystem（步/骑 + 塔）→ 全部建筑（BuildingEntity）。
- 只注册**存活**单位（Hp>0、View 未销毁）。
- 目录是**派生缓存**，不进存档；读档、Reset 后由 Tick 自动重建，天然一致。

### 4.3 注册口径（Kind 映射）

| 原始对象 | Kind | Key |
|---|---|---|
| 我方 ShipEntity | 0 | PLAYER |
| 敌方 ShipEntity | 0 | FactionId |
| 我方 GroundUnit（坦克/装甲车/导弹车） | 1 | PLAYER |
| 敌方 GroundUnit | 1 | FactionId |
| 我方 FriendlyUnit 步兵 | 2 | PLAYER |
| 敌方 EnemyUnit 步兵 | 2 | 所属 Faction.Name |
| 我方 BuildingEntity（attack 塔） | 3 | PLAYER |
| 我方 FriendlyUnit 骑兵 | 4 | PLAYER |
| 敌方 EnemyUnit 骑兵 | 4 | 所属 Faction.Name |
| 我方 BuildingEntity（非塔，含墙/房屋/设施） | 5 | PLAYER |

> 塔与建筑都来自 `S.Buildings`：`GetFunc("attack")>0` 归 Kind=3，其余归 Kind=5。**树木不来自 S.Buildings**（VegetationSystem 独立管理），故天然不注册、不可破坏。

## 5. 索敌规则

### 5.1 统一索敌接口

```csharp
public CombatTarget NearestHostile(float x, float z, float range, string myKey);
```
- 遍历 `Targets`，条件：`t.Key != myKey` 且平面距离 ≤ `range`。
- 返回距离最近者；无则 null。

### 5.2 各单位索敌半径（沿用既有口径，calculator 复算：格 × Tile=4）

| 单位 | 索敌半径（格） | 世界单位 | 有效射程 |
|---|---|---|---|
| 军舰 | 200（V9.4.3 口径） | **800** | 随武器等级 |
| 军车 | 60 | **240** | 8~20 格（32~80） |
| 骑兵 | 28 | **112** | 近战 |
| 步兵 | 22 | **88** | 近战 |
| 箭塔 | 15 | 60 | 15 格（60） |
| 火塔 | 12 | 48 | 12 格（48） |
| 炮塔 | 20 | 80 | 20 格（80） |
| 碉堡 | 18 | 72 | 18 格（72） |

- 索敌半径由调用方按自己的等级/类型传入；统一目录只负责"找阵营不同的目标"，不改变各单位的数值。
- 各单位思考节流（ThinkCd / AttackCd 沿用），不做每帧全员 O(n) 索敌。

### 5.3 地形可达性（最小约束）

- 不额外施加"军舰不能打陆地 / 坦克不能打海"的硬限制——**射程本身即约束**：
  - 军舰在海上，射程内可炮击近岸陆地目标（舰炮对地，合理）。
  - 坦克在陆地，射程内可轰击近岸水面目标（岸防火力，合理）。
  - 步兵射程短，军舰不贴岸则打不到，自然受限。
- 各单位的**移动**仍受原有地形约束（军车不下水、军舰不上陆），本版只改"索敌/攻击"，不改移动。

## 6. 攻击与伤害分发

### 6.1 开火流程

```
索敌(NearestHostile) → 距离 ≤ 有效射程? → 是: 开火(Damage)
                                          → 否: 按原逻辑追击（航速加成）
无目标 → 按原逻辑巡航 / 编队
```

### 6.2 统一伤害入口

```csharp
public void Damage(CombatTarget t, float dmg);
```
按 `t.Kind` 与 `t.Ref` 分发到各系统：

| Kind | Ref 类型 | 伤害落点 | 击杀/摧毁处理 |
|---|---|---|---|
| 0 | ShipEntity | NavalSystem.DamageShip | 击沉：销毁视图、移出列表（沿用既有） |
| 1 | GroundUnit | GroundWarfareSystem.DamageGround | 击毁：销毁视图、移出列表、编队中心更新 |
| 2 | EnemyUnit / FriendlyUnit | MilitarySystem.DamageInf | 步兵阵亡：销毁视图、移出/账面同步 |
| 4 | EnemyUnit / FriendlyUnit | MilitarySystem.DamageCav | 骑兵阵亡：MilCavalry 账面同步 |
| 3 | BuildingEntity（塔） | 直接扣 BuildingEntity.Hp | Hp≤0：DestroyByEnemy（不返还） |
| 5 | BuildingEntity（建筑） | 直接扣 BuildingEntity.Hp | Hp≤0：DestroyByEnemy（不返还） |

### 6.3 投射物接线（塔）

- 塔仍保留箭/火/炮**视觉投射物**：`FireProjectile` 的目标由 `EnemyUnit` 改为承载 `CombatTarget`（ProjectileEntity.Target 本就是 object）。
- `UpdateProjectiles` 命中时不再直接改 EnemyUnit，统一调 `CombatSystem.Damage(target, dmg)`。
- 投射物按开火瞬间锁定的目标位置飞行（飞行约 2s）；火塔 AOE、炮塔溅射沿用既有口径。

### 6.4 建筑破坏（需求 3）

- 所有非树建筑注册为可受击目标（Kind=3/5）。
- 敌方军舰炮击、军车、步兵、骑兵均可攻击射程内的我方建筑。
- 建筑 Hp 归零 → `GM.Building.DestroyByEnemy`（**不返还资源**，沿用 V6.1.3 起的口径）。
- 树木不注册，任何单位都不会以树为目标，也不会被 AOE 波及摧毁。

## 7. 生命周期与存档

| 状态 | 创建 | 刷新 | 销毁/退出 | 读档恢复 |
|---|---|---|---|---|
| CombatSystem 目录 | 战斗系统初始化后 | 4Hz 清空重建 | 游戏退出/Reset 自然清空 | Tick 自动重建，无需存档 |
| 五类单位 | 沿用各系统原有建造/生成 | 各系统 Tick | 各系统原有击杀逻辑 | 单位本身存档口径已覆盖 |
| 建筑 | 沿用建造系统 | 建筑 Tick | DestroyByEnemy | 建筑存档已覆盖 |

- 统一目录为**纯派生数据**，不落盘，避免存档与实际单位不一致。
- 读档后首个 Tick（≤0.25s）即重建出完整目标集合，攻击不中断。
- 不改变任何既有存档字段与结构，向后兼容旧存档。

## 8. 性能预算

| 项 | 规模 | 成本 |
|---|---|---|
| 注册目标总数 | 船≤200 + 车≤60 + 步骑≈100 + 建筑≤300 ≈ **660** | 4Hz 收集，每帧均摊极低 |
| 单次索敌 | O(660) | 各单位 ThinkCd 节流（0.3~0.5s 一次），非每帧全员 |
| 伤害分发 | O(1) 查表 + 类型分支 | 可忽略 |
| 视图/投射物 | 沿用既有程序化生成与对象数 | 无新增渲染负担 |

- 不新增每帧 660 规模的遍历峰值：索敌只发生在单位思考 tick，且各系统错峰。

## 11. 浏览器回归验证报告（实际执行）

### 11.1 第一轮（v947r2）：军车跨类型攻击端到端成立

跳时代到公元1949（Year4949/Era6）→ WebBuildGround 造我方 2 辆军车、敌方镜像 2 辆，高频 probe 时间线：

| 时刻 | 我方 | 敌方 | 说明 |
|---|---|---|---|
| 第4秒 | ours=2 | enemy=2 | 双方各 2，faction=2 |
| 第8秒 | ours=0 | enemy=1 | 我方 2 辆全灭、敌方 1 辆被击毁 |
| 第12秒 | ours=0 | enemy=0 | 敌方最后 1 辆被绕大陆巡航的军舰 / 塔 / 步骑**跨类型**击杀 |

证明跨类型索敌（NearestHostile）与多阵营互攻有效，敌方各派互打的链路被打通。海军镜像、舰载机（白双翼 / 灰喷气 / 棕螺旋桨多形态，航母自动发射）、存档读档（WebQuickSave / WebQuickLoad 后同步加载、随后恢复，目录重建）均通过。

### 11.2 关键 Bug：海军"只在岸边、不交战"

第一轮暴露：造我方 5 艘军舰（共 6）、敌方镜像 6 艘后，CombatProbe 显示 **PLAYER=69、east_0=1**——6 艘敌船全部被错误归入 PLAYER。

**根因（逐行确认）**：
- `SpawnEnemyShip` / `SpawnEnemyAt` / Debug 镜像都走 `LeastRepresentedFaction()` 分配阵营；
- 该方法开头 `if(_enemyFactions.Count==0) return default;`，**首调时阵营从未初始化**（只有 `RandomFaction()` 会调 `EnsureFactions()`，而镜像路径不走它）；
- 于是敌船 `FactionId=null` → 注册时 Add 空 key 被兜底为 **PLAYER** → 敌船与我方同阵营，`NearestHostile`（Key 不同才敌对）永不把它们当敌人。

### 11.3 两处修复

| # | 位置 | 修复 |
|---|---|---|
| 1 | `LeastRepresentedFaction()` 开头 | 补 `EnsureFactions();`，确保首调即初始化 3-5 敌阵营（红海海盗 / 黑旗帮 / 南蛮水师 / 北洋余部 / 联合舰队） |
| 2 | `DebugSpawnOwnWarships()` | 现代演示船改用现代军舰（25% 航母 / 50% 导弹舰 / 余驱逐舰，Defs 缺失回落 cannon_ship），原硬编码木炮船导致我方在现代仍全是过时木船、迅速全灭 |

### 11.4 第二轮（v947r3）：阵营修复 + 海战击沉闭环

阵营修复后 CombatProbe（阵营修复通过证据）：
`total=74 ship=12 | PLAYER=56 联合舰队=1 红海海盗=1 北洋余部=1 南蛮水师=2 黑旗帮=1 west_1=12`
——6 艘敌船均衡分配到 5 个海洋阵营（与 PLAYER 不同、互相之间也不同）。

强制海战 WebForceNavalBattle 后约 30 秒，**海战击沉闭环成立**：
- 修复前（阵营错误）：双方完全不交战，船数恒定；
- 修复后：我方 6 → 0（全沉）、敌方 6 → 2（4 艘被击沉），战斗目录 total 74→41，证明双方激烈互相攻击。

### 11.5 最终轮（v947r4）：平衡修复后双方均有击沉

平衡修复（我方现代军舰）后，强制海战并连续 probe：
